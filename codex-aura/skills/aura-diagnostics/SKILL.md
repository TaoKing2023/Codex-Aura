# Aura 诊断

先查明失败发生在哪一层，再处理实际原因。用户要求修复且范围已明确时继续完成必要修复；诊断技能不自动增加授权或放宽运行模式。

1. 调用 `aura_doctor({probe_mcp:true})`，检查 CLI、登录状态、固定模型配置、路由健康、stdio 启动和 MCP `initialize` / `tools/list`。只检查路径时可设 `probe_mcp:false`。自检不调用 `get_unreal_context`、编译、资产编辑或截图工具；不要为验证连接增加这些有副作用的操作。
2. 调用 `aura_permissions`，提供实际 `mode`、`active_tool`、精确 `project_dir` / `project_name` 和本轮真实 `user_text`；没有这些信息时说明缺失，不伪装 Agent 或用历史消息充当授权。此工具解释现有边界，不授予权限。
3. 根据实际输出区分故障：

   - **stdio 无法启动或握手失败：** 核对 executable、参数和配置文件路径。指出具体失败 server；工具目录不可达时先处理这一层。
   - **UE 编辑器未连接：** 路由健康、握手成功或存在工具目录均不证明编辑器 ready。需要资产验证时，仅使用已允许的 `aura_get_blueprint_meta` / `aura_get_blueprint_graph` 对核实过的规范对象路径安全回读。
   - **`approval_policy=never` 且工具要求审批：** 报告具体工具和原始拒绝原因；检查已审核 guarded 工具的专用审批配置是否缺失。工具名看起来只读不足以证明安全，不能给全部 MCP 工具 blanket approval。
   - **精确工程闸门拒绝：** 对照实际工程目录及当前用户授权，不用相似项目名或改成测试路径消除拒绝。
   - **工具开关关闭或 Ask / Plan 限制：** 报告实际模式及被阻止的步骤；不自动启用工具、切 Agent、编译或改资产。

配置修复只覆盖用户已授权的具体问题。覆盖软件或配置前，按用户及当前工程约定备份受影响内容；安装器默认使用用户本地数据目录下的 `Aura\CodexAura\backups`，也可明确指定备份目录。保留既有工程授权边界，修复后重跑相关自检或安全读取验证。不要修改全局审批模式、绕开拒绝、查看登录凭据内容，也不要盲目重复提交可能仍在执行的重操作。

默认中文交付：具体失败层、已核实原因、已完成修复与验证；未能完成时说明具体工具、实际拒绝及剩余步骤。无需新增广泛审批流程或反复询问已有授权。
